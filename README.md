# WeChat-Auto-Response

[![License: Apache 2.0](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://www.apache.org/licenses/LICENSE-2.0)

基于视觉的、非侵入式的微信自动回复程序，调用 DeepSeek（或任意 OpenAI 兼容接口）API，
通过 OCR 识别聊天内容后自动生成并发送回复。纯屏幕级操作，无封号风险。

## 特性

- **图形界面**：内置 tkinter GUI，点击框选区域、一键启动/停止、实时日志，区域自动记忆
- **区域选择**：启动时框选联系人列表区域与聊天窗口区域
- **多会话自动回复**：检测联系人头像右上角红色未读角标，识别发信人并自动切换会话
- **联系人白名单 + 多 AI 人设**：只回复白名单内联系人，且每人可绑定不同人设
- **消息归属判断**：靠左=对方消息、靠右/绿色气泡=我方消息，只回复对方的最新一条
- **动态上下文**：根据新消息内容动态裁剪发给 AI 的历史，尽量省 token
- **聊天记录持久化**：按联系人分文件保存，重启后不重复回复
- **联系人长期记忆**：从聊天中提炼对方的家乡/生日/喜好等信息（memory.json）
- **双平台兼容**：自动识别 macOS / Windows
- **「请喝杯咖啡」提示**：GUI 右上角常驻微信/支付宝付款码缩略图（点击打开原图扫码）；
  命令行模式在启动与退出时打印提示文案并自动打开收款码原图（`SHOW_DONATE=false` 可关闭）

## 安装与使用

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

（Windows 用户还会额外安装 `pygetwindow` 用于窗口激活；macOS 无需。）

### 2. 配置环境变量

复制 `.env.example` 为 `.env` 并填入真实值：

```bash
cp .env.example .env
```

`.env` 中需要配置（其余项可省略、用默认值）：

| 配置 | 说明 |
|---|---|
| `OPENAI_API_KEY` | DeepSeek / OpenAI 兼容接口的密钥 |
| `OPENAI_BASE_URL` | 接口地址，默认 `https://api.deepseek.com` |
| `OPENAI_MODEL` | 模型名，默认 `deepseek-chat` |
| `DRY_RUN` | `true` 时不调 API、用占位文本（调试用） |

> `.env` 已被 gitignore，请勿提交。完整配置项见 `.env.example`。

### 3. 初始化配置模板（可选）

仓库只包含脱敏模板，复制一份再按自己情况改；也可以跳过，GUI 里新建人设时会自动生成：

```bash
cp config/personas.example.json config/personas.json
cp config/stickers.example.json config/stickers.json   # 想用表情包功能时
```

### 4. 运行

**图形界面（推荐）：**

```bash
python wechatbot_gui.py
```

1. 点「① 框选联系人列表」「② 框选聊天窗口」，在定格的全屏画面上拖拽框选
   （Esc 取消）；区域自动记忆在 `config/regions.json`，下次启动免重选。
2. 点「▶ 启动自动回复」，日志实时显示在窗口中；「■ 停止」可随时结束主循环
   （当前轮处理完后退出）。
3. 勾选「测试模式」不真的发送，用于调试；点「人设配置」在界面内直接编辑人设
   （见下节），不再需要打开外部编辑器改 JSON。

**命令行方式：**

```bash
python wechatbot.py
```

启动后按提示框选区域：先框选左侧**联系人列表**，再框选右侧**聊天窗口**（共点 4 个角点）。
之后程序自动循环：检测未读角标 → 识别发信人 → 白名单过滤 → 切换会话 → 自动回复。

macOS 需要授予「屏幕录制」与「辅助功能」权限；Windows 无额外权限要求。

## 人设与白名单配置（config/personas.json）

```json
{
  "default_persona": "warm",
  "personas": {
    "warm":  { "name": "暖心女生朋友", "prompt": "..." },
    "work":  { "name": "干练同事",     "prompt": "..." }
  },
  "contacts": {
    "小明":   "warm",
    "同事群": "work",
    "小李":   null
  }
}
```

- `personas`：多个人设，key 自定义，`prompt` 即发给 AI 的 system prompt（也支持 `"key": "人设文本"` 简写）。
- `default_persona`：默认人设 key，**没有单独指定人设的联系人一律用它**。
- `contacts`：**键 = 自动回复白名单**，值 = 该联系人用的人设 key。
  - `"小明": "warm"` → 小明用 warm 人设
  - `"小李": null` → 小李在白名单内，用默认人设
  - `"小李": {"persona": "work", "enabled": false}` → 临时停用
  - `contacts` 留空 `{}` → 回复所有人（都用默认人设）
- 改完文件**无需重启**，下一轮循环自动生效；配置缺失或写错时回退兜底人设，不崩溃。

### 在 GUI 里编辑人设（推荐）

点主界面「人设配置」按钮打开编辑窗口，无需手写 JSON：

1. **列表页**：列出全部人设（标注哪个是默认），右侧「编辑」进入，「＋ 新增人设」创建新的。
2. **编辑页**：
   - **人设名字**：文本输入框。
   - **人设特点**（多选）：亲切／幽默／毒舌／暖心／温柔／傲娇／撒娇／话少／话痨／理性／直接／共情强。
     选中的按钮右上角显示红色 `×`，再点一次取消选中。
   - **人设身份**（单选）：老师／医生／律师／程序员／设计师／销售／HR／财务／老板／公务员／学生／客服。
   - **人设内容**：选完特点与身份后自动拼接生成，可直接手动改写；改过之后不会被选项覆盖，
     需要重来就点「↻ 按选项重新生成」。
   - **清空人设**：清空全部输入与选择。
   - **保存人设**：只有**内容有变更**且**名字／特点／身份三项都非空**时才可点击；
     不满足时按钮置灰，下方提示缺哪一项。
   - **删除人设**：新增模式不可用。若有人设正被联系人使用，删除时会把这些联系人
     自动改回默认人设并弹出提示，不会留下悬空引用。

保存后立即写回 `config/personas.json`，下一轮回复即生效（无需重启）。
新人设以「人设名字」作为 key；编辑已有人设时 key 保持不变，避免破坏 `contacts` 里的映射。
人设的可选字段 `identity` / `traits` 由本编辑器写入，老格式（只有 `prompt`）照常兼容。

## 联系人长期记忆（memory.json）

程序自动把每个联系人的重要信息（家乡、生日、工作地、年龄、喜好、习惯、近期计划等）提炼到 `memory.json`，与聊天记录分离。

- **触发时机**：每次回复后尝试更新，但有 **6 小时冷却期**（`MEMORY_ANALYZE_INTERVAL_HOURS`）；冷却期已过但无新记录时也跳过。
- **只发增量**：分析时只把 **已有记忆 + 最近 24 小时聊天记录** 发给 AI。
- **简要不重复**：AI 被要求保留整合、不重复堆叠；结果超长自动截断。
- **供回复回忆**：回复时把记忆注入 system prompt，让 AI 能"记得"对方（可关）。

| 配置 | 默认 | 说明 |
|---|---|---|
| `MEMORY_ANALYZE_HOURS` | `24` | 分析时只取最近 N 小时聊天记录 |
| `MEMORY_ANALYZE_INTERVAL_HOURS` | `6` | 触发分析的最短间隔（冷却期） |
| `MEMORY_INJECT_REPLY` | `true` | 回复时是否注入联系人记忆 |
| `MEMORY_MAX_CHARS` | `400` | 记忆文本长度上限 |

## 时间感知（隐含注入当前时间）

每次调用 AI 时，都会把**当前时间**以隐含方式写进 system prompt（不进聊天记录、不占对话轮次），
让 AI 有"现在几点、今天周几、隔了多久"的概念：

```
【当前时间】2026年09月12日 星期六 07点（清晨），距上一条消息 3 小时。……
```

- 包含**日期 + 星期 + 小时 + 时段**（凌晨/清晨/上午/中午/下午/晚上/深夜），
  AI 因此会说"早点睡""吃早饭了吗"这类合时宜的话，也能回答"今天几号""周末吗"。
- **距上一条消息多久**取自聊天记录里最后一条的时间戳：隔了半天再回时不会再说"刚才"。
- 提示里明确要求"除非对方问起，不要主动报时"，避免 AI 每句都复述时间。
- 记忆分析也带同样的时间，便于记下"他经常深夜找我"这类作息信息。
- **只到小时、不带分钟**：同一小时内这句文本完全一样，可以命中大模型的 prompt 前缀缓存，省钱。

| 配置 | 默认 | 说明 |
|---|---|---|
| `INJECT_TIME_HINT` | `true` | 是否注入时间（关掉后 AI 完全无时间概念） |

## 「请喝杯咖啡」付款码提示

**GUI 模式**：主界面**右上角**常驻「☕ 请我喝杯咖啡」小栏，显示微信/支付宝付款码
**缩略图**（64×64）。交互：

- 点击右侧 **✕** 收起二维码；再点「☕ 请我喝杯咖啡」标题重新展开（标题本身也是开关）。
- 二维码显示时，**点击任一缩略图弹出 360px 放大窗口**；窗口内可点「打开原图」
  用系统图片查看器打开原图（大图缩放显示可能仍扫不上，原图最稳）。

**命令行模式**：程序**启动时**和**退出时**（含 Ctrl+C 中断）各执行一次：console 打印
提示文案，同时自动打开 `img/` 目录下的微信/支付宝收款码**原图**。

- 图片按文件名关键字自动识别：含 `wechat` 的图 → 微信，含 `alipay` 的图 → 支付宝（jpg/jpeg/png 均可）。
- 打开动作走 `core/platform.open_file`：macOS 用 `open`、Windows 用 `os.startfile`、Linux 用 `xdg-open`。
- 图片缺失 / 加载失败时静默降级（GUI 直接不显示，命令行打印图片路径），绝不报错。

> 注：早期版本曾尝试在终端内用半块字符 + 真彩 ANSI 渲染二维码，实际显示异常且无法扫码，已废弃。

| 配置 | 默认 | 说明 |
|---|---|---|
| `SHOW_DONATE` | `true` | `false` 时 GUI 右上角不显示付款码栏，命令行也不打印提示、不打开预览 |

## 表情包功能

**发送**：AI 根据语境自主决定，在回复末尾返回 `[表情:情绪]` 标记（不会显示给对方），
程序解析后按 `config/stickers.json` 里「情绪 → 自定义表情面板第几个」的映射，
点击微信表情按钮 → 对应格子发出，**不需要 AI 理解每个表情包的含义**。

**接收**：对方发来表情包/大图时（聊天区最新内容是一大块 OCR 读不出文字的图像），
自动裁剪后交给**视觉模型**分析含义（相同图片按内容哈希缓存，只分析一次），
AI 拿到含义后正常回复，也可附表情回应。我方手动发的表情包会被识别并跳过。

使用步骤：

1. GUI 点「表情包配置」→ 在 `config/stickers.json` 预置的映射上修改（情绪 → 第几格），保存
2. 点「标定表情面板」按提示点击 5 处：①输入框左侧 ☺ 按钮 ②面板中的「自定义表情」分组 ③自定义表情第一行第一格中心 ④再次点 ☺ 按钮重开面板 ⑤第一行第二格中心
3. 点「测试发送」验证标定是否准确（向当前打开的聊天真实发送一张）
4. 理解对方表情包需配置视觉模型（`.env`）：`VISION_API_KEY` / `VISION_BASE_URL` / `VISION_MODEL`
   （如智谱 GLM-4V、阿里 Qwen-VL、OpenAI GPT-4o 等 OpenAI 兼容服务；DeepSeek 无视觉能力）
5. 未配置视觉模型时功能仍可用：收到的表情包按 `[表情包]` 占位处理，发送不受影响

| 配置 | 默认 | 说明 |
|---|---|---|
| `ENABLE_STICKERS` | `true` | 表情包功能总开关（AI 不再返回表情标记） |
| `VISION_API_KEY` / `VISION_BASE_URL` / `VISION_MODEL` | 空 | 视觉模型接入三项，用于理解收到的表情包 |

已知边界：表情面板坐标基于「窗口位置不变」的假设，微信窗口移动/缩放后需重新标定；
面板纵向前进步长按方格假设推算（= 横向间距），每行格数可在 stickers.json 的 `columns` 调整。
